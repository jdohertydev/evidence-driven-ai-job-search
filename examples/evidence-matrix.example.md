# Example requirement-to-evidence matrix

This simplified example shows how I separate evidence, gaps and confidence before writing application materials.

| Requirement | Evidence | Confidence | Treatment |
|---|---|---:|---|
| Workflow automation | n8n/OpenAI project; Zapier/VBA calendar automation | High | Lead evidence |
| AI-assisted workflows | Structured OpenAI use inside controlled n8n workflow | High | Lead evidence |
| Testing | Failure testing; dry runs; verification steps | High | Emphasise |
| Scripting | PowerShell, Python, VBA | High | Emphasise practical usage |
| APIs / webhooks | Portfolio project examples | Medium | Use precisely; avoid overclaiming |
| Documentation / handover | README documentation; historical training/support work | High | Emphasise |
| Power Automate | No direct hands-on evidence identified | Low | Do not claim experience |
| Entra / Intune / Copilot Studio | No substantial direct evidence identified | Low | Record as development area |

## Principle

The matrix is not designed to make every cell green.

A useful application should make strengths visible while also making unsupported claims difficult to introduce accidentally.
